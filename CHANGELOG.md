- `bin/bgrun` and new `bin/bgrun-container-guard` (ADE queue 85 (a)-(c)): a `container ...` command now (a) starts a down Apple `container` apiserver once before it runs (`container system start --disable-kernel-install`; `BG_CONTAINER_AUTOSTART=0` turns it off; exit 72 if it stays down), and (b) fails with exit 70 when the CLI exits 0 but reports an XPC "Connection invalid" error (any other status passes through; stdin, output and TERM/INT/HUP are relayed). - `bin/bgrun approve-local` tickets (operator 2026-11-21): `--for 7h` / `--until "tomorrow 8am"` [`--scope DIR`] [`-- CMD`] asks for ONE Touch ID and lets every `ci`-mode local run through until the expiry (shown as America/New_York 12-hour time in the dialog and the output); `status` (klist), `revoke [ID]` (kdestroy), `check [DIR]`, and `--ask` (a chooser: this run only / 1 h / 7 h / until a time). Tickets are 0600 files under `~/.local/state/bg/tickets/`, signed with a per-install salt (tamper-evidence, not a boundary), each use logged with time, directory and argv hash. The one-shot form is unchanged.

- `bin/bgrun` and new `bin/bgrun-container-guard` (ADE queue 85 (a)-(c)): a `container ...` command now (a) starts a down Apple `container` apiserver once before it runs (`container system start --disable-kernel-install`; `BG_CONTAINER_AUTOSTART=0` turns it off; exit 72 if it stays down), and (b) fails with exit 70 when the CLI exits 0 but reports an XPC "Connection invalid" error (any other status passes through; stdin, output and TERM/INT/HUP are relayed). - `bin/bgrun`: the admission gate's default `BG_MAX_LOAD_PER_CORE` rises from 3.0 to 5.0 (50 on the 10-core Mac) per the operator ruling of 2026-11-21 ("mac is still perfectly usable at 50"); the header comment and `docs/gradle-limits.md` (which still said 1.5) now agree, and `tests/test_bg_load_gate.py` pins the default (bg hands `load-watch admit --max-per-core 5.0` when the variable is unset). `load-watch`'s own admit base moves to 5.0 in djbclark-ade, so bg's value is no longer the tighter one. Memory-churn, swap-in and free-memory gates are unchanged. (2026-11-21)

- Prepared an opt-in ADE NATS JetStream module for vps-hub with tailnet-only authenticated clients, local monitoring, runtime-only credentials, synchronous persistent storage, and isolated NixOS VM/host CI. Activation remains disabled pending review and live acceptance. (2026-11-18; https://github.com/djbclark/djbclark-ade/issues/779)

- `bin/bg approve-local`: the authentication call (`sudo-ask`, or `sudo -k` without it) now runs under `env -i` with only a fixed PATH, HOME, USER, LANG and TERM, so a caller's `BASH_ENV`, `ENV`, `PYTHONSTARTUP`, `LD_*`/`DYLD_*`, `IFS`, `LC_*` or PATH entries no longer reach sudo-ask or sudo (bg's own shell still honours BASH_ENV, same user); LANG, TERM and USER are forwarded only when they are plain names. (2026-11-15)
- Added `roles/git_ignore` (`just git-ignore-check` / `git-ignore-apply`): the global git excludes file `~/.config/git/ignore` is now tracked and installed from the repo; a differing live file is shown as a diff and refused unless `-e git_ignore_adopt=true`. (2026-11-15)
