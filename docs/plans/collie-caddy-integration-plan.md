# Collie Caddy Integration Plan

## Objective

Collie (Herdr mobile web UI, AltanS/collie v0.20.2) is installed and running
but served via standalone `tailscale serve` on `mac.greyhound-sidemirror.ts.net`,
bypassing the site's Caddy TLS front door. This creates two paths to the
machine (Caddy on ports 80/443, Tailscale Serve on the tailnet interface :443).
The goal is to bring Collie under Caddy so there's one TLS termination point.

### Target

`https://mac.greyhound-sidemirror.ts.net/collie/` through Caddy on :443. The
bridge stays on loopback, Collie stops publishing any `tailscale serve`
mapping, and Caddy is the only ingress.

1. **Caddy (stayturgid template change).** Add a block gated on
   `'collie-bridge' in ports`, next to the LiteLLM one:

   ```caddy
   @collie_bare path /collie
   redir @collie_bare /collie/ 308
   handle_path /collie/* {
   	reverse_proxy 127.0.0.1:{{ ports['collie-bridge'] }} {
   		header_up -Tailscale-User-Login
   		header_up -Tailscale-User-Name
   		header_up -Tailscale-User-Profile-Pic
   	}
   }
   ```

   `handle_path` is what Collie's `docs/deployment.md` ("Serving Collie under a
   path") gives for Caddy; the bridge accepts the prefix stripped or not.
   Header stripping matters: behind Caddy nothing injects Tailscale identity
   headers, so a tailnet client could otherwise forge `Tailscale-User-Login`.
   Validated 2026-10-09 with `caddy adapt` on the rendered fragment.
2. **Collie `.env`** (Variant C plus a path mount, Collie `docs/deployment.md`):

   ```bash
   COLLIE_SKIP_SERVE=1                       # Caddy is the ingress; no tailscale serve
   COLLIE_BASE_PATH=/collie
   COLLIE_PUBLIC_HOSTS=mac.greyhound-sidemirror.ts.net   # Host validation fails closed without it
   COLLIE_ALLOWED_ORIGINS=https://mac.greyhound-sidemirror.ts.net
   COLLIE_PUBLIC_URL=https://mac.greyhound-sidemirror.ts.net/collie/
   # remove COLLIE_SERVE_PORT and COLLIE_TRUSTED_USER: no Tailscale identity
   # reaches the bridge through Caddy; device pairing is the gate
   ```

   Do not set `COLLIE_DEVICE_HEADER`: Caddy authenticates no device, and the
   header would only give a forgeable write path.
3. **Auth.** Collie 1.18.0 makes pairing mandatory for every `/api/*` read.
   Update to 1.18.0 first (#219), pair the phone, then move the door.
4. **The phone.** The PWA, its pairing token and its push subscription are
   bound to the origin and path, so the move is a new app: remove the old
   `:8788` icon, open `/collie/`, run `collie pair` and claim it, add to the
   home screen, re-enable notifications.

### Steps (operator; nothing here has been applied)

1. Collie 1.18.0 and a paired phone (#219).
2. Merge the stayturgid template change; in this repo `just site-sync`, then
   reload Caddy (`just site-serverapps apps=caddy`; fragment-only changes did
   not restart Caddy as of review MF-4, so confirm the route is live).
3. Edit the Collie `.env` as above, then `collie restart`, then `collie doctor`
   (its `front-door` line must name `/collie`).
4. Remove Collie's old mapping if `collie restart` left it:
   `tailscale serve --https=8788 off`; `tailscale serve status` should list
   only what Caddy and the funnel need.
5. Verify: `curl -s https://mac.greyhound-sidemirror.ts.net/collie/api/health`
   returns JSON (not landing-page HTML); an unpaired `/collie/api/snapshot`
   returns 403; the phone works after re-pairing; a push notification arrives.
6. Merge the `registry/ports.yml` collie-bridge row change (caddy_path
   `/collie/*`, no `tailscale_serve_port`).

Rollback: restore the `.env` (put back COLLIE_SERVE_PORT=8788 and
COLLIE_TRUSTED_USER, drop the new keys), `collie restart`; the Caddy route is
harmless while unused.

### Wrapper script (`launchd-wrapper.sh`)

```bash
#!/bin/bash
set -euo pipefail
CONFIG_DIR="${HERDR_PLUGIN_CONFIG_DIR:-$HOME/.config/herdr/plugins/config/herdr.collie}"
if [ -f "${CONFIG_DIR}/.env" ]; then
  set -a; . "${CONFIG_DIR}/.env"; set +a
fi
COLLIE_ROOT="${COLLIE_ROOT:-$HOME/.collie}"
export HERDR_SOCKET_PATH="${HERDR_SOCKET_PATH:-$HOME/.config/herdr/herdr.sock}"
export COLLIE_STATE_DIR="${COLLIE_STATE_DIR:-${COLLIE_ROOT}/data}"
export HERDR_PLUGIN_CONFIG_DIR="$CONFIG_DIR"
exec /opt/homebrew/bin/bun run "${COLLIE_ROOT}/bridge/index.ts"
```

The `.env` is sourced by the wrapper rather than inlined in the plist so config
can be updated without `launchctl bootout`/`launchctl bootstrap`.

## The Caddy Integration

### Why

Currently two HTTPS paths serve this machine:

1. **Caddy** (com.djbclark.caddy) — ports 80 (redirect) + 443 (HTTPS) on the
   physical network interface. Serves the main site.
2. **Tailscale Serve** (tailscaled) — intercepts the tailnet's :443 on the
   Tailscale virtual interface. Serves Collie.

While these don't conflict (Tailscale Serve operates at a different network
layer), having two ingress paths is messy long-term. Caddy should be the sole
TLS front door.

### How

The bridge listens on `http://127.0.0.1:8787` (loopback only). Caddy can proxy
to it via a `handle` or `reverse_proxy` directive.

**Option A: Caddy handles it directly**

Add to Caddyfile (path-based or subdomain-based):

```caddy
mac.greyhound-sidemirror.ts.net {
    # Existing site config...
    
    handle /collie/* {
        reverse_proxy 127.0.0.1:8787
    }
}
```

Then remove the `tailscale serve --bg 8787` mapping:

```bash
tailscale serve --https=443 off
```

Update the Collie config to set `COLLIE_PUBLIC_HOSTS` to the magic DNS name
(host-header validation). Re-point the tailnet URL.

**Option B: Subdomain approach**

If Caddy handles a broader set of services, a subdomain per service:

```
collie.mac.greyhound-sidemirror.ts.net {
    reverse_proxy 127.0.0.1:8787
}
```

**Option A (path-based)** is simpler for the current one-machine setup.

### Steps

- [ ] Update Caddyfile in site-djbclark to proxy for Collie
- [ ] Set `COLLIE_PUBLIC_HOSTS=mac.greyhound-sidemirror.ts.net` in `.env`
- [ ] Remove `tailscale serve --https=443 off` (or `tailscale serve --bg 0`)
- [ ] Verify: `curl https://mac.greyhound-sidemirror.ts.net/collie/` returns Collie UI
- [ ] Update the Collie `.env` to remove `COLLIE_PORT` and `COLLIE_HOST` if Caddy determines routing
- [ ] Update port registry `registry/ports.yml` to note Collie on 8787

### Port registry update

Add to `~/ops/site-djbclark/registry/ports.yml` under mac:

```yaml
- {port: 8787,  bind: "127.0.0.1", owner: site, service: collie-bridge, status: active,
   note: "Com.djbclark.collie launchd agent; proxied via Caddy from tailnet hostname"}
```
