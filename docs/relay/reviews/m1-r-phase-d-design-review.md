  post-D8.

  shell5555/CFEngine probes, notifications, FIRERPA fallback, auto-heal — no
  O-V-G-O equivalent exists or is planned yet.
- **`access_monitor.py`:** ADB/TCP reachability state + notifications — no
  equivalent.
- **`just health`:** still surfaces unique live signal (D7 session proved
  hd8 `watchdog_stale` + p7a `bootloop_down`).

**Disposition: retain everything D7 retained — nothing is retire-able in M1.**

producer, or Grafana panels re-pointed at OpenObserve logs); (3) action/

## D8 per-device compatibility disposition

- **s24, p7a: verified.** Live-path markers exact-count 1 (22 s / 7 s);
  offline/reconnect cycle proven on the pilot (resume from checkpoints, no
  replay storm); second applies changed=0. Conforms to design §3 in full.
- **hd8: `pending-incompatible-runtime` — classified as an isolated
  compatibility recovery item, NOT a correctness/safety defect of D8 and NOT
  an accepted-forever limitation.** The official contrib binary SIGSYSes under
  Fire OS seccomp during cilium/ebpf memcg capability probing — an upstream
  binary/runtime interaction, not a rollout error. D8's live handling was
  correct (security not weakened, boot entry removed, process absent,
  binary/config retained). **However the configuration does not persist that
  decision (MF-2, must-fix):** the next hd8 deploy re-runs the probe and
  hard-fails the whole role.
  **Safe recovery strategy (recorded for a post-M1-Q step; do not attempt in
  M1-F):** build a minimal custom collector with OCB (OpenTelemetry Collector
  Builder) containing only filelog + file_storage + memory_limiter + batch +
  otlphttp — the memcg probe ships with components the pipeline does not use;
  a minimal manifest very likely avoids the seccomp'd syscall. Pin the OCB
  build reproducibly (version + module sums), extend `cache_otelcol.py`'s
  checksum/ELF gate to the custom artifact, pilot on hd8 with the §3.4
  marker + offline verifies, keep `stayturgid_otelcol_enabled: false` until
  the pilot passes. Never weaken device seccomp/security to accommodate the
  stock binary. Until then, hd8 stays covered by the retained D7 monitors.

## Verdict

Phase D (D2–D8) is a **faithful, verifiable execution of the front-loaded
design**: mode/exit-code/namespace contracts conform, MF-1(R1) is cloned
everywhere, D6's projection machinery is exemplary (including finding and
fixing the D5 zero-hosts bug), D7's retirement was genuinely coverage-gated
and rehearsed, and D8's supply-chain handling is the best in the repo. All
suites, identity, contract, and registry checks are green on both pulled
masters and all nine live endpoints answer 200.

**Not clean, with five must-fixes — none requiring rollback, all cheap and
sharply scoped:** live secret exposure in 0644 plists (MF-1, the only live
issue, introduced when D8 made the credentials real), a fleet-deploy landmine
on hd8 (MF-2), two launchd reload-semantics gaps that make future config
changes silently inert (MF-3, MF-4 — the same bug class D8 already had to
repair live for vector), and unpinned binary installs predating D8's own
better pattern (MF-5). Plus three cheap architecture fixes (A-10 header
churn, A-11 identity regression, A-12 stale panel labels). **M1-F executes
these; M1-Q takes the quality list; R3 remains after M1-Q.**
