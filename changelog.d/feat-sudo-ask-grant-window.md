
### Added

- `sudo-ask` approval window (`roles/sudo_ask_grant`): `sudo-ask --grant [DURATION]` (default 8h, max 24h, one dialog + Touch ID), `--revoke`, `--status`. While a window is open `sudo-ask CMD...` runs through the root helper `sudo-ask-granted` with no dialog, except a denylist (sudoers, PAM, the helper and grant file, the sudo-secretspec broker, TCC, keychain, disk erase, csrutil, nvram, user/admin changes), which still prompts. The grant file is root-owned; the sudoers drop-in allows only `exec`, `status` and `revoke` (no arguments) without a password and sets `timestamp_timeout=0`; the same drop-in turns the shared sudo ticket off for the operator (`Defaults:USER timestamp_timeout=0`; `10-timestamp-global` is not touched, rollback removes the line); `grant` proves fresh authentication from the kernel: every ancestor must be `/usr/bin/sudo` by the kernel's executable path, name and setuid-root uids (argv alone is self-asserted), and the outermost must be exactly `sudo -k HELPER grant DURATION` run by the invoking user with nothing but sudo between; the install checks the ticket setting (`LC_ALL=C sudo -n -l`, the user's defaults section must end at 0 and no other entry may give a ticket) and undoes itself if the check fails, and `--verify` fails if a plain `sudo -n true` succeeds (this reads the listed defaults; the behavioural proof is the runbook's `sudo -v; sudo -n /usr/bin/true` step); `grant` runs only from the installed path, and `sudo-ask` runs its own sudo as `sudo -k`; anyone who holds a sudo ticket is root, so only the ticket being off stops a ticket holder from opening or extending a window; code running as root inside an open window can rewrite the grant file and extend the window (accepted limit; `--status` warns when the file expires later than granted). Inside a window, code the invoking user can write (scripts and programs under their home, repos, `/tmp`, `/var/folders`, nosuid volumes, ACL-writable) or created since the grant still prompts; `exec` runs the realpath it judged; only system tools run unprompted. Programs that run code from their own arguments (awk, sqlite3, vim, less/man, m4, zip, dtrace, lldb, tar -I, rsync -e, scp/sftp -S, git -c/-C, interpreter library modules) are denied; this is hardening, not a boundary: an open window runs agent code as root. The persistence paths (LaunchDaemons and their program targets, `/usr/local/bin`, PrivilegedHelperTools, login window hooks, setuid/setgid changes, periodic, `/etc/paths*`, root shell rc, ssh) are on the denylist; `--revoke` and `sudo-ask --status --audit` report setuid files and launchd targets changed since the grant. Setup script with `--print`, `--check --diff`, `--verify`, `--rollback`; 12 mutants killed. `bin/approval-gate` (`status`, `check`, `ask`; registry `config/approval-gates.toml`) is the one place that decides whether a window covers a gate; `sudo-ask` (including the `-k` probe form) and `bgrun approve-local` (one-shot token, tickets capped at the window's end, `--ask` chooser skipped) call it. The setup script's install, `--verify` and `--rollback` refuse without `--live`. (#304)
