
### Added

- `sudo-ask` approval window (`roles/sudo_ask_grant`): `sudo-ask --grant [DURATION]` (default 8h, max 24h, one dialog + Touch ID), `--revoke`, `--status`. While a window is open `sudo-ask CMD...` runs through the root helper `sudo-ask-granted` with no dialog, except a denylist (sudoers, PAM, the helper and grant file, the sudo-secretspec broker, TCC, keychain, disk erase, csrutil, nvram, user/admin changes), which still prompts. The grant file is root-owned; the sudoers drop-in allows only `exec`, `status` and `revoke` (no arguments) without a password and sets `timestamp_timeout=0`; the same drop-in turns the shared sudo ticket off for the operator (`Defaults:USER timestamp_timeout=0`; `10-timestamp-global` is not touched, rollback removes the line); `grant` proves fresh authentication from the kernel's exact argv and real uid of its ancestors (only `/usr/bin/sudo -k HELPER grant DURATION` run by the invoking user, with nothing but sudo processes between) and runs only from the installed path, and `sudo-ask` runs its own sudo as `sudo -k`, so a cached sudo ticket cannot open or extend a window. Inside a window, code the invoking user can write (scripts and programs under their home, repos, `/tmp`, `/var/folders`, nosuid volumes, ACL-writable) or created since the grant still prompts; `exec` runs the realpath it judged; only system tools run unprompted. Programs that run code from their own arguments (awk, sqlite3, vim, less/man, m4, zip, dtrace, lldb, tar -I, rsync -e, scp/sftp -S, git -c/-C, interpreter library modules) are denied; this is hardening, not a boundary: an open window runs agent code as root. The persistence paths (LaunchDaemons and their program targets, `/usr/local/bin`, PrivilegedHelperTools, login window hooks, setuid/setgid changes, periodic, `/etc/paths*`, root shell rc, ssh) are on the denylist; `--revoke` and `sudo-ask --status --audit` report setuid files and launchd targets changed since the grant. Setup script with `--print`, `--check --diff`, `--verify`, `--rollback`; 12 mutants killed. `bin/approval-gate` (`status`, `check`, `ask`; registry `config/approval-gates.toml`) is the one place that decides whether a window covers a gate; `sudo-ask` (including the `-k` probe form) and `bgrun approve-local` (one-shot token, tickets capped at the window's end, `--ask` chooser skipped) call it. The setup script's install, `--verify` and `--rollback` refuse without `--live`. (#304)
