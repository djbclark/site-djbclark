### Fixed

- `bin/bgrun-container-guard` (the LOW findings of the review of PR 299): Ctrl-C delivery is decided when the INT arrives, not at start (`/dev/tty` + `tcgetpgrp` in the handler), so a run brought to the foreground with `fg` gets one INT per Ctrl-C (it used to get two, the second press being the CLI's fourth signal), and a `kill -INT PID` to a run sent to the background is forwarded instead of swallowed; a `kill -INT PID` sent while the run is the foreground group still looks like a Ctrl-C and is not forwarded (header). New tests pin the debounce edges: a TERM after the window, a different signal right after a TERM, and a steady stream of TERMs are all forwarded; mutants (shared window, sliding window, 30 s window, start-latched INT decision, always and never forward INT) are killed. (#PR)
